# 文案规范（Copywriting）

界面文案的唯一口径。改任何一句面向用户的字之前先读这一页；改完如果这里对不上，改这里。

## 一、四条原则

1. **动词优先**。按钮和菜单项写动作，不写描述。
   - 对：`保存` `删除` `开始复习` `新建项目` `提取`
   - 错：`点击此处保存` `一键智能提取` `去制卡页自己建`
2. **只说事实，不加情绪**。成功反馈不感叹号、不自夸、不延伸意义。
   - 对：`已保存` `已同步 12 项` `已删除`
   - 错：`云端双向同步备份成功！共合并了 12 项自律历史数据。`
3. **解释只留一句**。产品里的每段说明最多一句，超出就删——长解释是"说教味"的主要来源。
   - 对：`一天最多放几张新卡进复习队列。超出的顺延到明天。`
   - 错：`宁可少做，不可积压——一次建太多、第二天还不完，是弃坑最常见的原因。`
4. **错误直奔原因**，不铺垫、不"请您"。
   - 对：`未登录，无法同步` `未配置 Supabase 环境变量` `图片不能超过 4MB`
   - 错：`授权失败：请先输入邮箱并发送魔法链接登录后再同步。`

## 二、逐类规则

| 位置 | 规则 | 例 |
| --- | --- | --- |
| 弹窗标题 | 动作短语，不带疑问词 | `删除卡片`、`设定今日意图` |
| 确认描述 | `确定[动作][对象]？` + 一句后果 | `确定删除这个习惯？打卡记录会保留。` |
| 确认按钮 | 用动词，不用「确定」 | `删除`、`恢复`、`跳过` |
| 取消按钮 | 统一 `取消` | — |
| Toast 成功 | `已 + 动词` | `已保存`、`已登录`、`已同步 12 项` |
| Toast 失败 | 原因，不带"请重试" | `同步失败：连接超时` |
| 进行中 | `正在 + 动词…` | `同步习惯…`、`提取中…`、`正在生成下一个问题…` |
| 表单 Label | 名词，去掉"您的/用户/名称/分级" | `名称`、`组数`、`能量阻力`、`题型` |
| 选填标注 | 一律 `选填` | 不用「可选」「可留空」「非必填」 |
| Placeholder | 范例或短动作，不用"请输入…" | `例：晚上能安心关电脑`、`里程碑内容` |
| 排序/筛选 | 结果前置，不用"按…" | `题型混排`、`主题混排` |
| 括号 | 不塞英文对照，除非是方法论本身 | `WOOP`、`SM-2` 保留；`(Add Habit)`、`(Today)` 删掉 |
| 省略号 | 统一中文 `…` | `加载中…` |

## 三、术语固定

- 一级导航：`今日` / `复习` / `输出` / `制卡` / `看板` / `设置`
- 卡片：界面统一叫「卡」，不叫"闪卡""记忆卡片"混用（列表标题可保留「卡片记忆库」）
- 意图：`今日意图`（WOOP 四段写作 `愿望 / 结果 / 障碍 / 应对`）
- 习惯：`前置习惯`（不写"前置依赖""捆绑习惯"）
- 能量：`能量`（1–10），`能量阻力`（轻松 / 中等 / 挑战）
- 四档评级：`忘记` / `困难` / `良好` / `简单`——任何地方出现三档说法都是错的

## 四、两处易错

1. **数据层文案也要改**。`gate.ts`（首屏）、`feynman.ts`（提示）、`types.ts`（评级 hint/action）、`db.ts`（种子卡）里的字符串都会直接渲染，改文案时别只改 `.tsx`。
2. **同一句话不要写两遍**。心情标签曾同时存在于 `habit-data.ts` 的 `MOOD_LABELS` 和 `SpecializedRecordModal` 里，措辞已经漂移过一次；现在弹窗只读 `MOOD_LABELS`。新增文案前先搜一遍有没有同义句。
